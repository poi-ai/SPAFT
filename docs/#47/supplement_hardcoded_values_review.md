## 1. 固定値の全列挙と分類

`indicator.py` 内で呼び出し元から変更できない固定値を全て列挙する。

| # | メソッド | 固定値 | 内容 | 判定 |
|---|---|---|---|---|
| A | `get_bollinger_bands()` | `[1, 2, 3]` | 計算するσ倍率の水準リスト | **△ 変数化の余地あり** |
| B | `get_bollinger_bands()` | `sigma_tmp * 2` | bandwidthの定義（±1σ幅） | ✅ 数学的固定値 |
| C | `get_bollinger_bands()` | `upper_1_alpha` / `lower_1_alpha` 参照 | upper_diff / lower_diff / position が ±1σ基準で固定 | ✅ 数学的固定値（Aと連動） |
| D | `get_macd()` | `[1, 3, 5, 10]` | MACDの傾き計算に使う本数リスト | **❌ 変数化すべき** |
| E | `get_macd()` | `300` | 傾き計算スキップの閾値 `interval * count >= 300` | **△ 根拠をコメント化すべき** |
| F | `get_ichimoku_cloud()` | `long_window_size * 2` | 先行スパン2の期間（基準線期間の2倍） | ✅ 指標定義の固定値 |

## 2. 個別評価

### A. `get_bollinger_bands()` — `for sigma in [1, 2, 3]`

```python
for sigma in [1, 2, 3]:
    df_resampled[f'{column_name}_upper_{sigma}_alpha'] = ...
    df_resampled[f'{column_name}_lower_{sigma}_alpha'] = ...
```

**意味:** ±1σ、±2σ、±3σ の3水準のバンドを一括計算・追加する。

**固定値の妥当性:**

統計的に、正規分布に従う場合の価格がバンド内に収まる確率は:
- ±1σ: 68.3%
- ±2σ: 95.4%（最も広く使われる基準）
- ±3σ: 99.7%

3水準を常に計算すること自体は一般的で妥当。ただし、現在の実装では **B・C（upper_diff, lower_diff, position）が ±1σ を固定参照** しているため、sigma=1 は削除できない構造になっている。

**変数化の余地:**

`sigma_levels=[1, 2, 3]` として引数化することは可能だが、B・Cの計算（upper_diff, lower_diff, position）が ±1σ 固定であるため、完全な変数化には B・C 側も修正が必要になる。

**結論:** 現状の `[1, 2, 3]` は標準的で妥当。変数化のメリットが薄いため、**現状維持を推奨。**

---

### B・C. `get_bollinger_bands()` — `sigma_tmp * 2` / `upper_1_alpha` 参照

```python
# B: bandwidthを ±1σ幅（= upper_1alpha - lower_1alpha）として定義
df_resampled[f'{column_name}_width'] = (df_resampled['sigma_tmp'] * 2).round(3)

# C: upper_diff / lower_diff / position が ±1σ を基準とする
df_resampled[f'{column_name}_upper_diff'] = (price - upper_1_alpha).round(3)
df_resampled[f'{column_name}_lower_diff'] = (lower_1_alpha - price).round(3)
df_resampled[f'{column_name}_position']   = (price - lower_1_alpha) / width
```

**意味:**
- `width` = ±1σバンドの全幅（upper_1α - lower_1α = 2σ）→ `σ * 2` は数学的に正確
- `upper_diff` = 価格が ±1σ上限からどれだけ離れているか
- `lower_diff` = 価格が ±1σ下限からどれだけ離れているか
- `position` = ±1σバンド内での価格の相対位置（0 = 下限, 1 = 上限, 0.5 = 中心）

**妥当性:** いずれも ±1σ を基準にするのは一般的な設計（±1σ突破が最初の警戒シグナル）。
`position` が [0, 1] に正規化される点も扱いやすい。

**結論:** **固定値として完全に妥当。変更不要。**

### D. `get_macd()` — `for count in [1, 3, 5, 10]`

```python
# MACDとMACDシグナルの傾きを計算
for count in [1, 3, 5, 10]:
    if interval * count >= 300:
        continue
    df_resampled[f'{macd}_{count}_slope'] = (df_resampled[macd].diff(count)).round(3)
    df_resampled[f'{macd_signal}_{count}_slope'] = (df_resampled[macd_signal].diff(count)).round(3)
```

**意味:** MACDと MACDシグナルについて、それぞれ「count本前との差分」= 傾き（Slope）を計算する。
`diff(count)` は `値[i] - 値[i-count]` であり、N期間での変化量を表す。

**現在の実際の動作（interval=1, short=12, long=26, signal=9の場合）:**

| count | 意味 |
|---|---|
| 1 | 1本前（1分前）との差 → 最も短期のモメンタム |
| 3 | 3本前（3分前）との差 |
| 5 | 5本前（5分前）との差 |
| 10 | 10本前（10分前）との差 |

**固定値の問題点:**

- `[1, 3, 5, 10]` の選択根拠がコード上に明示されていない
- 他の指標のwindow_sizeはすべて引数として呼び出し元から指定できるが、ここだけハードコード
- interval が変わると意味も変わるが、それに対応する選択が行われていない
  - `interval=5` なら `count=1 → 5分変化, count=10 → 50分変化`
  - `interval=1` なら `count=1 → 1分変化, count=10 → 10分変化`

**妥当性の評価（interval=1の場合）:**

1分足MACD(12,26,9)のslope計算として `[1, 3, 5, 10]` は:
- 1分・3分・5分・10分の変化量を捉え、短期から中期までのモメンタムを段階的に表現している
- スキャルピング用途として短期寄りの選択で合理的
- ただし `count=10`（10分変化）と `count=1`（1分変化）の組み合わせが最適かは実測データで検証が必要

**結論:** 現状の `[1, 3, 5, 10]` の値は interval=1 に対して概ね妥当だが、**引数として変数化すべき。** 将来的に interval や trading strategy が変わったときに呼び出し元から調整できるようにするべき。

```python
# 推奨する修正イメージ
def get_macd(self, df, column_name, short_window_size, long_window_size, signal_window_size,
             interval, price_column_name='current_price',
             slope_periods=[1, 3, 5, 10]):   # ← 追加
    ...
    for count in slope_periods:
        ...
```

### E. `get_macd()` — `if interval * count >= 300`

```python
for count in [1, 3, 5, 10]:
    # 幅が長すぎるとデータが取れないのでスキップ
    if interval * count >= 300:
        continue
```

**意味:** `interval × count` が 300以上になる組み合わせでは傾き計算をスキップする。

**300という値の根拠:**

東証の1営業日の取引時間:
- 前場: 9:00〜11:30 = 150分
- 後場: 12:30〜15:30 = 180分（大引けクロージング込み）
- **合計: 330分**

300分 ≈ 1日の取引時間（約330分）。つまり「1営業日を超える期間の傾きは計算対象外」という意図と推定される。

**各intervalでの挙動:**

| interval | count=1 | count=3 | count=5 | count=10 |
|---|---|---|---|---|
| 1分足 | 1 ✓ | 3 ✓ | 5 ✓ | 10 ✓ |
| 5分足 | 5 ✓ | 15 ✓ | 25 ✓ | 50 ✓ |
| 15分足 | 15 ✓ | 45 ✓ | 75 ✓ | 150 ✓ |
| 30分足 | 30 ✓ | 90 ✓ | 150 ✓ | **300 skip** |
| 60分足 | 60 ✓ | 180 ✓ | **300 skip** | **600 skip** |

30分足/count=10（= 300分 = 1日分の変化）が**ちょうど境界でスキップ**される点は若干気になる（`>=300` なのでスキップ）。1日分の傾きは情報として有用な可能性もある。`> 300` または `> 330`（実際の1日分）に変更する余地がある。

**結論:** 値としては概ね妥当だが、**コードコメントで根拠を明示すること推奨。** `>= 300` の境界値については `> 330`（実際の1日取引時間）への変更を検討する余地がある。また D の変数化と合わせて引数化も可能。

### F. `get_ichimoku_cloud()` — `long_window_size * 2`

```python
# 先行スパン2の計算 long_window_size x 2本の高値と安値の平均をlong_window_size本先にずらす
df_resampled[leading_span_b] = (
    (df_resampled[high_column_name].rolling(window=long_window_size * 2).max()
     + df_resampled[low_column_name].rolling(window=long_window_size * 2).min()) / 2
).shift(long_window_size).round(3)
```

**意味:** 先行スパン2は「基準線期間の2倍」の高値・安値平均を「基準線期間先」に表示する。

**妥当性:** これは一目均衡表の **定義そのもの**。

一目均衡表（日足標準: 転換=9, 基準=26, 先行2=52）:
- 先行スパン2 = 52日間(= 26 × 2)の高値・安値平均 → 26日先に表示
- `52 = long_window_size * 2` は固定の関係式であり、パラメータではない

`long_window_size = 26` を変更した場合（例: 13/26→26相当の設定）でも、先行スパン2の期間は自動的に `long_window_size * 2` になるため、この計算は正しい。

**結論:** **指標の数学的定義として固定が正しい。変更不要。**

## 3. 呼び出し元のパラメータ妥当性

`board_mold.py` / `past_record_mold.py` で使用されている実際のパラメータ値の妥当性を評価する。

### 3.1 対象指標ごとの設定値

#### SMA / EMA / WMA / ボリンジャーバンド

```python
window_size_list = [3, 5, 10, 15]
```

| window | 1分足での意味 | 評価 |
|---|---|---|
| 3本 | 3分MA | 超短期。ノイズが多いがスキャルピングでは有効 |
| 5本 | 5分MA | 短期の定番。板情報や5分足トレンドと整合 |
| 10本 | 10分MA | 前場/後場の流れを捉える |
| 15本 | 15分MA | やや中期。15分足の区切りと対応 |

**評価: ✅ スキャルピング用途として妥当。** ただし `minute * window_size > 150` のフィルタにより、長い足では使用されるwindowが限定される（例: 10分足ではwindow=3, 5のみ）。

#### RSI / RCI

```python
window_size_list2 = [9, 14, 22, 26, 52]
```

| window | 評価 |
|---|---|
| 9 | 短期RSI。スキャルピングで頻用 |
| 14 | Wilder's RSI の標準値。最も一般的 |
| 22 | やや長め。月次ベースに相当 |
| 26 | 基準線(一目均衡表)と同期間 |
| 52 | 長期RSI。1分足データでは26分・52分の指標になる |

**評価: ✅ 多様な時間軸を網羅しており、ML特徴量としての多様性を確保している。** ただし52本のRSIは1分足で52分間のモメンタムを表すが、学習データの最初の52行はNaNになる点に留意。

#### PSY（サイコロジカルライン）

```python
window_size_list3 = [10, 12, 15]
```

| window | 評価 |
|---|---|
| 10 | 短期PSY |
| 12 | 一般的な標準値（月の営業日数に由来） |
| 15 | やや長め |

**評価: ✅ 妥当。**

#### パラボリックSAR

```python
af_list = [[0.01, 0.1], [0.02, 0.2], [0.05, 0.5], [0.1, 1.0]]
```

| min_af / max_af | 評価 |
|---|---|
| 0.01 / 0.1 | 保守的。トレンドへの追従が遅い |
| 0.02 / 0.2 | **Wilder's 標準設定**。最も一般的 |
| 0.05 / 0.5 | やや積極的 |
| 0.1 / 1.0 | **非常に積極的。** max_af=1.0のとき、af=max_afになるとSARがEPと一致し、次の足でトレンド反転が確定的になる。実運用には注意が必要だが、ML特徴量としては「過敏なSAR」として意味のある情報を持つ |

**評価: ✅ 多様な感度のSARを提供しており、ML特徴量として有効。** ただし `[0.1, 1.0]` は実際のトレードシグナルとしては使いにくい値。ML学習用の特徴量としては問題ない。

#### MACD

```python
short_window_size = 12
long_window_size = 26
signal_window_size = 9
```

| パラメータ | 日足標準 | 1分足での意味 | 評価 |
|---|---|---|---|
| short=12 | 12日EMA | 12分のEMA | ✅ 短期の流れを捉える |
| long=26 | 26日EMA | 26分のEMA | ✅ 基準線相当の中期EMA |
| signal=9 | 9日EMA | 9分のEMA | ✅ MACDを平滑化するシグナル線 |

**評価: ✅ 12/26/9はMACDの世界標準パラメータ。** 日足で使われる値をそのまま1分足に適用しているが、EWMは期間に比例してスムージングされるため、1分足でも短期のモメンタムを合理的に表現できる。

#### 一目均衡表

```python
short_window_size = 9   # 転換線
long_window_size = 26   # 基準線
```

| パラメータ | 日足標準 | 1分足での意味 | 評価 |
|---|---|---|---|
| short=9 | 9日（約2週間） | 9分の高値・安値平均 | ✅ 転換線の短期版として妥当 |
| long=26 | 26日（約1ヶ月） | 26分の高値・安値平均 | ✅ 基準線の短期版として妥当 |

先行スパン2 = `26 * 2 = 52`本（52分間）の高値・安値平均

**評価: ✅ 9/26は一目均衡表の元祖の設定。** 1分足への適用でも短期トレンドの均衡点として意味を持つ。

## 4. 判定まとめ

### 4.1 固定値の対応方針

| # | 固定値 | 対応方針 | 優先度 |
|---|---|---|---|
| **D** | `get_macd()` の `[1, 3, 5, 10]`（傾き計算本数） | **変数化すべき** → `slope_periods` 引数を追加 | 高 |
| **E** | `get_macd()` の `300`（スキップ閾値） | コメントで根拠を明示。`>= 300` → `> 330` への変更も検討 | 中 |
| A | `get_bollinger_bands()` の `[1, 2, 3]`（σ水準） | 現状維持（B・Cと密結合のため変数化コスト高） | 低 |
| B・C | ±1σ参照固定値 | 現状維持（数学的に正しい） | 不要 |
| F | `long_window_size * 2`（先行スパン2） | 現状維持（指標定義の固定値） | 不要 |

### 4.3 スコープ外の懸念事項（参考）

以下は今回の調査対象外だが、今後検討に値する点:

- **MACD short/long の選択**: 12/26 は日足標準だが、1分足スキャルピングに最適かは実績データで検証が必要
- **RSI の計算方式**: 現在は Cutler's RSI（単純移動平均ベース）を採用。Wilder's RSI（指数平滑移動平均ベース）の方が一般的とも言われる。ただし結果の差は軽微であり、ML学習上の影響は小さい
