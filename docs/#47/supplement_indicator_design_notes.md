## 1. intervalリサンプリング方式

### 1.1 現在の実装

```python
# indicator.py 各メソッド共通
if interval > 1:
    df_resampled = df[[price_column_name]].iloc[::interval, :].copy()
```

`iloc[::interval]` は**行インデックスベース**の等間隔抽出。
行番号 0, interval, 2*interval, ... を抽出するため、実時刻を参照しない。

### 1.2 問題の発生条件

**問題が発生するのは `interval > 1` の場合のみ。**
`interval=1`（1分足そのまま）では一切問題は生じない。

前場150本（9:00〜11:29）・後場175本（12:30〜15:24）の325本構成の場合、
`interval=5` でのリサンプリング例:

| 抽出行インデックス | 実際の時刻 | 備考 |
|---|---|---|
| ... | ... | |
| 145 | 11:25（前場） | |
| **150** | **12:30（後場）** | ← **行インデックス上は「次の5分足」** |
| 155 | 12:35（後場） | |

行145（11:25）と行150（12:30）は、行インデックス上は5行差だが、
実時刻では **65分差**（前場終了〜後場開始の昼休み60分＋5分）。

### 1.3 各アプローチの比較

#### 行インデックスベース（現状）

**メリット**
- 国内証券会社の提供するチャートの大多数が採用している方式に一致する
  - 前場・後場を「連続した取引時間」として扱い、昼休みの空白を表示しない
  - 投資家が目にするチャートと同じN分足になるため、学習データとの整合性が高い
- 特別気配・連続約定気配による**欠けたバー**（例: 10:15がない）を自然に扱える
  - 時刻ベースだと欠損バーに NaN が生じ、ローリング計算が壊れる
- 実装がシンプルで決定的

**デメリット**
- 昼休みをまたぐ「1本」だけが実際には `interval*60分 + 昼休み60分` に相当し、
  他の本と時間的に等価ではない
- この「またぎバー」での価格変動は、前場引け値→後場寄り値の変動を含むため、
  純粋なN分足変動より大きくなりやすい → 統計的な外れ値リスク

#### 時刻ベース（pd.resample等）

**メリット**
- 各バーが本来の時間幅に対応する（5分足なら必ず5分分のデータ）

**デメリット**
- 特別気配・連続約定気配で時刻が抜けた場合、欠損バーが NaN になる
  → rolling/ewm 計算がその NaN を無視できず、指標値が乱れる
- 昼休みをまたぐバー自体が存在しなくなるが、代わりに「前場最後のバー」が
  短時間しか計算できない（11:27〜11:30の3分だけなど）
- 実装が複雑（resampleのohlc集約、NaN補完戦略が必要）
- 投資家が見るチャートとN分足の形が一致しなくなる

### 1.4 影響の定量的評価

1日のリサンプリング本数と昼休きまたぎバーの割合:

| interval | 1日の本数（概算） | またぎバー数 | 割合 |
|---|---|---|---|
| 1（1分足） | 325 | 0 | **0%（問題なし）** |
| 5（5分足） | 65 | 1 | ~1.5% |
| 15（15分足） | 22 | 1 | ~4.5% |
| 30（30分足） | 11 | 1 | ~9% |
| 60（60分足） | 6 | 1 | ~17% |

`interval=1` が主な用途であれば実質的な影響はない。
`interval=5` でも影響は1日1本（~1.5%）にとどまる。

### 1.5 外れ値リスクの具体例

仮に前場が下落トレンドで後場が急反発する日（よくあるパターン）を想定:

```
行145（11:25） close=28,000円
行150（12:30） close=28,300円  ← 昼またぎで+300円

5分足SMA(3)の計算:
  抽出行: ..., 140(11:20, 27900), 145(11:25, 28000), 150(12:30, 28300) ...
  この3本の平均: (27900 + 28000 + 28300) / 3 = 28067円
  → 通常の5分足SMAと値は大きく変わらないが、
    145→150の変化量が実際より大きく計上される
```

`change_price`（変動額）では `28300 - 28000 = +300円` が「5分間の変動」として記録されるが、
実際は65分間の変動。この行だけ **外れ値** になりやすい。

ただし、ML学習（CatBoost）においてはこの外れ値パターン自体が
「昼休み後の値動き」として一定の一貫性を持つため、モデルがパターンとして学習する可能性もある。

### 1.6 結論（判断材料の整理）

| 観点 | 行インデックス | 時刻ベース |
|---|---|---|
| 国内チャートとの整合性 | ✅ 一致する | ❌ 一致しない |
| 特別気配対応 | ✅ 自然に対応 | ❌ NaN が生じる |
| 昼休きまたぎバーの正確さ | ❌ 不正確（1本） | ✅ 正確 |
| 実装複雑性 | ✅ 低い | ❌ 高い |
| interval=1時の影響 | ✅ なし | ✅ なし |

**最終的には設計方針の判断。** ただし以下を踏まえると行インデックスベースの維持が合理的:
- `interval=1` 主体なら影響ゼロ
- 国内証券チャートとの整合性が高い
- 特別気配への耐性がある
- 昼またぎバーの外れ値は1日1本のみで、ML学習上の一貫性もある

もし採用する場合は、コメントに**設計上の意図**を明記し、
`change_price` 等の変動額指標では昼またぎバーを**特定・除外するオプション**を将来的に検討余地として残しておく。

## 2. RSI・RCI・PSY の先頭行NaN

### 2.1 各指標の計算原理と先頭NaNの必然性

#### RSI（相対力指数 / Relative Strength Index）

**計算式:**

```
差分[i]     = 終値[i] - 終値[i-1]
上昇幅[i]   = max(差分[i], 0)
下落幅[i]   = max(-差分[i], 0)
平均上昇幅  = rolling(window).mean(上昇幅)  ← window本の単純移動平均
平均下落幅  = rolling(window).mean(下落幅)
RS          = 平均上昇幅 / 平均下落幅
RSI         = 100 - 100 / (1 + RS)
```

**先頭NaNが必然な理由:**

- `差分[0]` は `終値[-1]` が存在しないため NaN
- `rolling(window).mean()` は window 本ぶんのデータが揃うまで NaN を返す
- RSI(9) の場合: 差分は row 1 から有効 → 平均は row 9 から有効（row 1〜9の9本）

理論的な最初の有効値: **row 9**（先頭9行 row 0〜8 が NaN）

**現在の実装の微細な誤差:**

```python
# indicator.py の実装
df_resampled['up'] = df_resampled['diff'].apply(lambda x: x if x > 0 else 0)
```

`diff[0] = NaN` に対して `NaN > 0` は `False` → `up[0] = 0`（ファントムゼロ）

この結果、`rolling(9).mean()` が row 8 で有効値を返すことになり、
**先頭NaNは8行**（理論的には9行が正確）になる。
また row 8 の値は `(0 + 実際の上昇幅row1〜8) / 9` となり、
**row 0 の phantom 0 を含む**ため若干不正確。row 9 以降は正確な計算に戻る。

| | 現在の実装 | 厳密な実装 |
|---|---|---|
| 先頭NaN行数 | 8行（row 0〜7） | 9行（row 0〜8） |
| 最初の有効値 | row 8（phantom 0 含む、微小誤差） | row 9（正確） |
| row 9 以降 | 正確 | 正確 |

影響は最初の有効値1行のみで、ML学習上の実害はほぼない。

---

#### RCI（順位相関指数 / Rank Correlation Index）

**計算式（スピアマン順位相関の変形）:**

```
n個のデータについて:
  時刻順の順位: d1[i] = i  (i = 1, 2, ..., n)
  価格順の順位: d2[i] = 価格が低い順の順位（1始まり）
  順位差: d[i] = d1[i] - d2[i]

RCI = (1 - 6 * Σ(d²) / (n * (n² - 1))) * 100

値域: -100〜+100
  +100: 時刻の古い順と価格の安い順が完全一致（単調上昇トレンド）
  -100: 完全逆相関（単調下落トレンド）
    0: 相関なし（ランダム）
```

**先頭NaNが必然な理由:**

RCIはローリング窓内の**全n個のデータが揃って初めて計算可能**な指標。
`n-1` 個では計算自体が数学的に定義できない（n個で1セットの公式）。

- `rolling(window).apply(calc_rci)` → window本揃うまで NaN
- RCI(9): row 8 が最初の有効値（先頭8行 row 0〜7 が NaN）

RSI・PSYと異なり、`diff()`を使わないため**ファントムゼロ問題はない**。
先頭の8行が NaN なのは完全に正しい挙動。

**Note:** 現在の実装では `df_resampled` 内で `ffill` した後に main df にマージしているが、
row 0〜7 の NaN は ffill では埋まらない（埋める対象の前の値が存在しない）ため、
これらの行は正しく NaN のままになる。

---

#### PSY（サイコロジカルライン / Psychological Line）

**計算式:**

```
差分[i]    = 終値[i] - 終値[i-1]
上昇フラグ[i] = 1（差分 > 0）または 0（差分 ≤ 0）
PSY        = rolling(window).sum(上昇フラグ) / window * 100

値域: 0〜100（%）
  75以上: 買われすぎゾーン
  25以下: 売られすぎゾーン
  50付近: 中立
```

**先頭NaNが必然な理由:**

- PSYは「直近n本中、前の本より上昇した本数の割合」
- 比較対象は `終値[i] vs 終値[i-1]` なので、row 0 は比較不能（NaN）
- `rolling(window).sum()` は window 本揃うまで NaN
- PSY(10): row 9 が最初の有効値（先頭9行 row 0〜8 が NaN）

**RSIと同様のファントムゼロ問題あり:**

```python
df_resampled['up'] = df_resampled['diff'].apply(lambda x: 1 if x > 0 else 0)
# diff[0] = NaN → NaN > 0 は False → up[0] = 0（ファントムゼロ）
```

row 9 の PSY 値は `(0 + 上昇フラグrow1〜9) / 10 * 100` = 9本の実データ+phantom 1本で計算される。
row 10 以降は正確な10本で計算される。

| | 現在の実装 | 厳密な実装 |
|---|---|---|
| 先頭NaN行数 | 9行（row 0〜8） | 10行（row 0〜9） |
| 最初の有効値 | row 9（phantom 0 含む） | row 10（正確） |
| row 10 以降 | 正確 | 正確 |

---

### 2.2 3指標の比較まとめ

| 指標 | window | 先頭NaN（現状） | 理論上の先頭NaN | ファントム問題 | 最初の有効値の正確さ |
|---|---|---|---|---|---|
| RSI | 9 | 8行 | 9行 | あり（diff→0扱い） | row 8 が微小誤差（1行のみ） |
| RCI | 9 | 8行 | 8行 | **なし** | **完全に正確** |
| PSY | 10 | 9行 | 10行 | あり（diff→0扱い） | row 9 が微小誤差（1行のみ） |

### 2.3 「先頭はNaNではないはずか」への回答

**NaNが正しい。** 3指標いずれも、window本未満のデータでは指標が数学的に定義できない。
「先頭はNaNであるべきでない」という考え方があるとすれば以下の2パターンが考えられるが、いずれも問題がある:

**パターンA: 利用可能なデータ数だけで計算する（部分計算）**

```python
# 例: RSI(9) の row 3 を rows 0〜3 の4本で計算
```

→ 9本で計算した RSI と 4本で計算した RSI は**異なる指標**になる。
初期値だけ異なる計算式で求めると、後続の正常値との連続性が断絶する。
ML学習においても「先頭部分は別の指標」という混乱を招く。

**パターンB: 固定値で埋める（-1, 0, 50, -999 等）**

→ RSIの場合、50（中立）で埋めるという手もあるが、
それは「50という強気でも弱気でもないシグナルが最初に続く」というデータを
ML に学習させることになり、意味論的に誤り。

**結論: NaNのままが唯一正しい選択肢。**
CatBoost は NaN をネイティブ処理するため、先頭の NaN 行が ML 学習に悪影響を与えることはない。

### 2.4 ファントムゼロ問題（RSI・PSY）を直すべきか

現状: 最初の有効値1行のみが phantom 0 を含み、微小に不正確。
修正コスト: `diff()` の NaN を `up`/`down` にも伝播させる（`lambda x: 0 if x > 0 else 0` を `lambda x: np.nan if pd.isna(x) else ...` に変更）。

修正した場合の効果:
- RSI(9): 先頭NaN が 8行→9行、row 9 の値が正確になる
- PSY(10): 先頭NaN が 9行→10行、row 10 の値が正確になる
- RCI: 変更不要（既に正確）

**優先度: 低。** 影響は各指標で最初の有効値1行のみ。
学習データ全体（1日325行）に対して1行の微小誤差は実害がほぼない。
issue #47 の主要スコープ（ML特徴量計算）では修正不要と考える。
ただし、将来的に指標の計算精度を厳密化する際に合わせて修正するのが望ましい。
